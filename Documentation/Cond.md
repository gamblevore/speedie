# Code Of Conduct


### About the Code of Conduct

The purpose of the code of conduct, is to create an environment, where positive contributions can grow. This document explains what we expect.

## Our Pledge

We pledge to create a friendly enviroment fostering the goals of improving software development.

We will act in ways that contribute to an open, welcoming, inclusive, and healthy community.

Those are common goals. But Speedie has more specific goals. Here they are:

* Making software development creative and productive.
* Reducing global harm by lowering energy-use, through efficient code and overall design.
* Playing with software, to push new boundaries. Increasing creativity.
* Reigniting the pushing of forgotten boundaries.


## Bugs Found

Speedie has bugs, like all software. Please report any bugs found via [GitHub's bugtracker](https://github.com/gamblevore/speedie/issues). Especially if that bug is stopping you from enjoying or using Speedie.


## Usage

Just using Speedie at all, for something important, is already beneficial to the language. So the easiest way to contribute, is just use Speedie.


## Patch Contributions

Most software, such as Linux, accepts patches, from people, who have an invested need, for those contributions, to be accepted. Perhaps they are a large company, who serves millions of people, and need some minor thing changed, and it will make their life soo much easier.

And then, this company would pay their employees, to add features that benefit all the users of the software... assuming that the maintainers of that software, accept it. (That is in addition to donating towards Linux itself.)

Thats something we need for Speedie.

However, in Speedie's case... we don't have that. We don't have a large community of people, who are deeply invested.

But, we still need, contributors... So... contributions or requests or issues raised, will be judged upon that standard.

Here are some examples of good and bad contributions:

* _I am not a user, I have no programs using speedie. Please add this XYZ feature._ -- This is not even a contribution.
    * _I have been using speedie for weeks / months / years, here is a patch to add XYZ feature_ -- This is better.
* _I added feature XYZ, however it is outside the plans of Speedie._ -- This has a chance of not being accepted. Its best to ask first, before adding something outside of the plans.
    * _I have added missing feature XYZ, that fits within your plans. (Such as improving Linux compatability for both ARM/x86)_ -- This is great.

Here are some usually good patches:

* _I've optimised some of your code to run faster or take less code_ -- We definitely want that! Assuming it is just as understandable (or more) than before.

* _I fixed a bug that caused crashes, or bad behaviour._ -- Quite likely to be accepted, assuming the fix itself does not add problems.

To make contributions that are beneficial to Speedie, look at [Speedie's "Road Map" section](https://github.com/gamblevore/speedie/blob/main/README.md#road-map-to-release) in the README.md file. To get an idea of what work needs doing.
